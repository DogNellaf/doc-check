# doc-check

[English](README.md) · Русский

Проверка договоров поставки и счетов с поиском по словам из
[ai-consultant](https://github.com/DogNellaf/ai-consultant) и без нейросети: работает примерно в 40 МБ
памяти. Договор от поставщика сверяется по
пунктам с эталоном компании и проверяется правилами её юриста. Счёт проверяется на арифметику, на
соответствие договору с поставщиком, согласованной спецификации и заказу. На выходе — вывод,
список замечаний с объяснением каждого, отчёт в Excel и файл Word: договор с правками в режиме
рецензирования и комментариями или письмо поставщику по счёту.

Демо-компания — «Колосок», вымышленная пекарня из ai-consultant, здесь она покупает муку, масло и
яйца. Поставщик, люди и реквизиты тоже вымышленные.

## Быстрый старт

```bash
docker compose up --build
```

Откройте http://localhost:8000/. Три примера проверяются при сборке образа, можно загрузить свой
PDF, скан (JPG, PNG или PDF из картинок), DOCX или TXT. Настраивать ничего не нужно, ключи не нужны.

## Что проверяется

**Договор** (DOCX, PDF, скан)

1. Текст режется на пункты с номерами (`3.3. Покупатель оплачивает…`) и названиями разделов.
   Стороны берутся из преамбулы («именуемое в дальнейшем «Поставщик»»), их реквизиты — из раздела
   реквизитов: таблицы в две колонки или блоков друг за другом.
2. Каждый пункт ставится в пару к пункту эталона по двум числам: насколько похожи тексты по
   сочетаниям букв, которые переживают русские окончания, с прибавкой за совпадающий номер пункта, и
   общие слова с весом по редкости (поиск ai-consultant). Пара засчитывается, только если оба числа
   проходят пороги, поэтому перенумерованный пункт находит свой эталон, а новый остаётся новым. На
   примерах пары получаются ровно те же, что давала модель multilingual-e5 в версии 0.1.
3. Пункт в паре с другими цифрами — «изменён», пункт эталона без пары — «отсутствует» (в Word он
   возвращается вставкой), пункт договора без пары — «нет в эталоне».
4. Каждое правило из `knowledge/kolosok/rules.toml` проходит по каждому пункту: предоплата больше
   30 %, неустойка покупателя выше 0,1 % в день или без предела, изменение цены в одностороннем
   порядке, оплата «на счёт, указанный в счёте», претензии в течение часов, суд поставщика и другие.
   Правило — это регулярное выражение, проверка (`forbid`, `require`, `max`, `min`) и объяснение
   словами. Юрист правит файл, а не код.
5. ИНН, ОГРН и счета проверяются по контрольным цифрам, расчётный счёт — вместе с БИК банка.

**Счёт** (PDF из учётной программы, скан)

- количество × цена в каждой строке, сумма строк против «Итого», НДС по правильной ставке (22 % с
  2026 года) и в правильной сумме, «Всего к оплате», сумма прописью против цифр;
- реквизиты получателя против договора с поставщиком: другой счёт или банк — главный признак
  поддельного счёта;
- основание: номер договора и заказа;
- каждая строка против спецификации и заказа, в пару их ставит тот же поиск, с проверкой фасовки
  и жирности («мешок 25 кг» — не «мешок 50 кг», «72,5 %» — не «82,5 %»).

В примерах заложено 25 ошибок. Приёмочный тест (`tests/test_smoke.py`, с настоящими порогами)
находит все 25 и ни одного замечания на эталоне, сверенном с самим собой, и на чистом счёте.

## Сканы

Страница без текстового слоя рисуется в 300 dpi и читается Tesseract (rus+eng) на сервере. Сначала
убираются линии таблицы: сетку Tesseract читает как `|` и `[` и теряет цифры рядом с ней. Потом
исправляются частые ошибки: `000 «` вместо `ООО «`, пробел внутри 20-значного счёта. Скан счёта из
примеров читается примерно за 5 секунд, в одном PDF до `OCR_MAX_PAGES` (5) сканированных страниц.

## Модель

`LLM_PROVIDER=none` (по умолчанию), `gigachat` или `openai`, за одним вызовом `complete()`
(`app/llm.py`), как в ai-consultant. Все проверки делает код, у модели одна задача: если правила не
нашли строк счёта (необычная вёрстка, плохой скан), она выписывает их в JSON, а код проверяет их как
любые другие. Ошибка модели тогда видна как расхождение, а не как ложное «всё хорошо». Условия
GigaChat: бесплатный пакет для физлиц — только для личного некоммерческого использования.
Сертификаты GigaChat выданы от корневого сертификата Минцифры (Russian Trusted Root CA), он лежит в
`certs/` и подключается сам.

## Память

Веб-процесс только отдаёт страницу, примеры и считает лимиты: около 40 МБ. Свой файл посетителя
проверяется в дочернем процессе (`app/worker.py`): он загружает pypdf, pdfium, Tesseract,
python-docx и openpyxl, делает работу, отдаёт результат и оба отчёта и завершается. Замер в Docker с
`--memory 256m`: в простое 36 МБ, проверка PDF или DOCX — пик около 100 МБ, скан — около 160 МБ
(Tesseract в один поток), после каждой проверки контейнер возвращается к размеру простоя. Проверка
дольше `CHECK_TIMEOUT` (80 с) останавливается. Примеры проверяются один раз при сборке образа
(`python -m app.precompute`), поэтому сервис стартует примерно за секунду.

## Лимиты

| Настройка | По умолчанию | Что происходит |
|---|---|---|
| `CHECKS_PER_DAY` | 10 | своих файлов с посетителя (IP, хеш с солью) в сутки, примеры бесплатны |
| `WORK_CONCURRENCY` | 1 | проверок одновременно, каждая в своём процессе; остальные ждут в очереди |
| `QUEUE_MAX` | 20 | больше — посетителя просят повторить через минуту |
| `DAILY_TOKEN_BUDGET` | 200 000 | модель отключается до конца суток |
| `UPLOAD_MAX_BYTES` | 5 МБ | и `MAX_PAGES` 15 |
| `RESULT_TTL` | 3600 | столько секунд отчёт можно скачать, не больше `RESULTS_MAX` (200) загрузок |
| `CHECK_TIMEOUT` | 80 | секунд, потом проверка останавливается |

## Данные

Загруженные файлы не хранятся: текст и отчёт живут в памяти час, для скачивания. Контейнер ничего
не пишет на диск. Демо-компания, её поставщик и все номера вымышленные; у реквизитов код региона 00,
которого нет ни у одной налоговой, поэтому они не могут принадлежать настоящей компании, хотя
контрольные цифры сходятся (кроме тех, где примеры ошибаются нарочно).

## Своя компания

В `COMPANY_DIR` лежат обычные файлы:

- `company.toml` — компания, ставка НДС, реквизиты и поставщики с подписанными договорами;
- `reference-supply.md` — эталон договора, разделы `## ` и пункты с номерами;
- `rules.toml` — правила юриста;
- `spec-*.csv` — спецификация с поставщиком, `name;unit;price`;
- `orders/*.csv` — заказы, `name;unit;qty`, номер и дата в первой строке-комментарии.

## Разработка

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt -r requirements-dev.txt
python scripts/make_examples.py          # пересобирает examples/ (reportlab, PT Sans под OFL)
python -m app.precompute                 # результаты примеров, как при сборке образа
pytest                                   # тестам OCR нужен tesseract с rus
ruff check . && ruff format --check .
```

Страница повторяет вертикальную раскладку дашборда [Tabler](https://tabler.io) 1.6.1 (MIT): в боковом
меню проверка, эталон договора, правила юриста, поставщики со спецификациями и заказы. Иконки [Lucide](https://lucide.dev)
(ISC), всё отдаётся самим приложением. PDF примеров набраны шрифтом PT Sans от ParaType (OFL).
